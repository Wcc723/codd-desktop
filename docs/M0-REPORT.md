# CODD Desktop: M0 report

Written 2026-10-16 after integration. Covers the holder, CoddCore, the app shell and the terminal-engine spike (each built and then reviewed), plus the integration run.

**Status:**
- **Builds and tests:** everything builds with zero warnings in our code, and all 400 tests pass.
- **Real holders:** the app can run zsh sessions in real `codd-holder` processes behind a DEBUG flag. A holder outlives an app quit, and the next launch reattaches to it.
- **Terminal engine:** not chosen yet. The spike's numbers are in, but its visible-window runs and the 注音 checks still need a rerun with the screen unlocked.

## 1. What was built

### Holder: `Packages/CoddHolder`
- **What it does:** one small process per session owns the terminal (PTY) and keeps the session alive when the app quits.
  - Darwin only, no Foundation, one event loop.
  - Keeps recent output in a memory-mapped ring buffer and writes `meta.json`.
  - Serves wire protocol v1 over a unix socket (`docs/ARCHITECTURE.md`).
  - A small output scanner tracks title, OSC 7 cwd, bell, progress, terminal modes and the replay start points.
  - Flow control, drop mode with GAP frames, a 10 s linger after the child exits, re-binding the socket if its file disappears.
- **Products:**
  - `CoddProtocol`: framing and messages, standard library only.
  - `CoddHolderCore`: the holder itself.
  - `CoddHolderClient`: a blocking client, the spawner (`posix_spawn` with SETSID and CLOEXEC_DEFAULT) and `meta.json` discovery.
  - `codd-holder` and `codd-holderctl` (a debug client).
- **Review:** fixed 7 defects. The main ones:
  - The shell came back blank after `vim`, `less` or `man` (wrong replay start point when leaving the alternate screen).
  - `CSI 3J` was wrongly treated as a replay start point.
  - Modes inside one combined escape sequence were lost.
  - The control queue grew without limit.
  - An exit that happened before the holder started watching for it was missed.

### Core: `Packages/CoddCore`
- **Hook state machine:** a port of `status-writer.js` `applyEvent`. It is checked against golden fixtures generated by the unmodified JS: 22 scenarios with 167 events, plus 44 merge scenarios. A separate desktop mode adds the extensions listed in decision 9.
- **Other parts:**
  - Claude registry reader.
  - Terminal title parser.
  - cswap models and an actor client.
  - Account ordering (R7) and auto-switch (R8) as pure functions.
  - Launch builder: argv, environment and the per-session `--settings` hook JSON.
  - Login-shell environment capture.
  - An atomic, versioned layout store.
- **Review:** fixed 8 defects. The main ones:
  - Login-shell capture hung for 5 s whenever CODD had a controlling terminal. The command runner was rewritten on `posix_spawn` with its own session.
  - `--resume` reopened a stale conversation after `/clear`.
  - A crashed session's hook state stayed frozen. Added `relaunchBaseline`.
  - The registry reader could block on a FIFO.
  - An older build could downgrade a newer layout file.

### App shell: `App/`
- **UI:** AppKit throughout:
  - NSOutlineView sidebar with tree and state modes, drag and drop, inline rename and context menus.
  - Rail, session pane with header, banner and answer bar.
  - Menu bar status item with a panel.
  - ⌘K palette.
  - Dock badge.
- **Data:** the mock store is seeded with SPEC §5. The terminal is reached only through the `TerminalSurface` protocol; a fake surface draws the mock transcripts.
- **Review:** fixed 19 defects. The main ones:
  - Groups, projects and sections never collapsed.
  - Visible idle CPU was over budget. The waiting-lamp pulse moved from a 2 Hz app timer to Core Animation.
  - Banner and answer-bar buttons were rebuilt every second.
  - The app icon cost 16 MB.

### Terminal spike: `Spikes/TermSpike`
- **What it is:** libghostty (`libghostty-spm`, Metal) and SwiftTerm 1.99.0 side by side, each on its own PTY.
- **Measurements:** `--probe` (Claude's startup queries, key encodings, replay) and `--bench` (throughput, memory, key latency, a 256 MiB PTY flood). `--report` regenerates `RESULTS.md`.
- **Manual checks:** `MANUAL-TEST.md` covers 注音, Claude, paste, selection, links and resize.
- **Review:** fixed 9 issues. The main ones:
  - Ghostty sent no keys after it was told the child exited.
  - Ghostty's output queue had no limit.
  - The probe accepted replies that Claude itself rejects.

### Integration (this run)
- **`project.yml`:**
  - The CODD target depends on the `CoddCore`, `CoddProtocol` and `CoddHolderClient` products, and on the `codd-holder` tool target (built first, not linked).
  - **"Embed codd-holder"** build phase: copies `codd-holder` to `CODD.app/Contents/MacOS/` and signs it ad-hoc with the identifier `app.fancycodd.codd-holder`.
    - It removes the old file first, so the copy is always a new file on disk. Holders outlive the app and keep running from the old file; overwriting a running, signed executable in place makes the kernel kill those holders.
    - The phase only reruns when its inputs change.
  - `codd-holder` target settings:
    - `OTHER_LDFLAGS: -Xlinker -dead_strip_dylibs`, so Foundation is not linked (checked with `otool -L`).
    - `ENABLE_DEBUG_DYLIB: NO`, so the holder is one self-contained file.
    - `SKIP_INSTALL: YES`.
  - The shell's resources and settings, and the `CODDTests` target, are kept.
- **`App/Real/`** (new), active only with the DEBUG launch argument `-codd-real-holders`. Mock mode stays the default, and Release builds ignore every option.

| File | Purpose |
|---|---|
| `RealModeOptions.swift` | Parses the launch options: `-codd-real-holders [YES/NO]`, `-codd-data-root <dir>` or the `CODD_DATA_ROOT` variable, `-codd-spawn-shell <cwd>/YES`, `-codd-shell-argv "<argv>"`, `-codd-quit-after <s>` and `-codd-snapshot <png>`. |
| `CoddDataRoot.swift` | `sessions/` and `run/` under the data root, created with mode 0700. `sessions/` is excluded from Time Machine. Socket path is `run/<8 hex>.sock` and is checked against the 103-byte limit. |
| `HolderLink.swift` | Non-blocking control connection to one holder, on its own dispatch queue: HELLO with takeover, then WELCOME, TITLE, CWD, BELL, EXIT, ERROR and PING replies, delivered to the main actor in order. It never sends ATTACH, so no terminal bytes reach the main actor. |
| `HolderLauncher.swift` | Builds the shell's argv and exact environment with CoddCore's `LaunchBuilder`, writes the env file (mode 0600, deleted once the socket is up) and starts the holder with `HolderSpawner`. The holder itself gets a minimal environment, so `DYLD_*` variables from Xcode never reach it. Waits up to 3 s for the socket. |
| `ChildReaper.swift` | Reaps the holders this app run spawned, so none become zombies. Handles an exit that happened before the watch started. |
| `HolderSessionStore.swift`, `+Layout.swift` | The real `SessionStore`. At launch it reads `sessions/*/meta.json` off the main thread and reattaches to live holders. It shows the OSC title, OSC 7 cwd, SHELL / EXITED (with the exit code) / STOPPED, and uptime. STOP sends SIGTERM to the holder after checking the pid is still a holder. RESTART / RESUME start a new holder in the same directory, so the ring continues. Deleting an ended session removes its directory. Layout intents work like the mock's, in memory only. |
| `RealPaneText.swift` | Pane placeholder text: there is no terminal engine yet. |

- **Wiring:**
  - `AppDelegate` picks the store at launch.
  - "新增 Shell" in the sidebar's + menu and "新增 session" in the menu bar panel start a zsh session in real mode.
  - On quit the app only closes the connections; the holders keep running.
- **Tests:** `App/Tests/RealHolderTests.swift`, 9 tests. Option parsing and data-root paths, plus two tests against real holders (the copy embedded in the app) in a temp folder:
  - The link receives WELCOME, the title and EXIT.
  - Store test:
    1. Spawn a session.
    2. Disconnect; the holder stays alive.
    3. A new store discovers the session and reattaches.
    4. STOP; the row shows EXITED.
    5. Delete the session's history.

## 2. How to run each thing

```sh
cd <repo>

# Packages (separate scratch paths avoid lock clashes)
swift test --package-path Packages/CoddHolder --scratch-path .build-holder
swift test --package-path Packages/CoddCore   --scratch-path .build-core
# holder release numbers
swift build -c release --package-path Packages/CoddHolder --scratch-path .build-holder
CODD_HOLDER_PRODUCTS=$PWD/.build-holder/out/Products/Release \
  swift test --package-path Packages/CoddHolder --scratch-path .build-holder --filter MeasurementTests
# inspect sessions / holders
.build-holder/debug/codd-holderctl list --root <dataRoot>/sessions
.build-holder/debug/codd-holderctl tail --socket <dataRoot>/run/<hex>.sock --from resync --no-follow

# App (CODD + embedded codd-holder)
xcodegen generate
xcodebuild -project CODD.xcodeproj -scheme CODD -configuration Debug -derivedDataPath build/dd build   # or: test
APP=build/dd/Build/Products/Debug/CODD.app/Contents/MacOS/CODD
$APP -CODDSelfTest YES -CODDForceVisibleTimers YES      # outline fuzz + shortcuts + timers, prints SELFTEST OK
$APP -CODDMetrics YES -CODDForceVisibleTimers YES       # launch / switch / memory, then exits
$APP -CODDSnapshotDir /path/to/dir                      # PNGs of the main window, panel and palette

# Real-holder mode (DEBUG only). ALWAYS pass a data root while testing; without one it uses
# ~/Library/Application Support/CODD. Keep the root short: socket paths must stay under 104 bytes.
ROOT=$(mktemp -d "${TMPDIR}codd-m0.XXXXXX")
$APP -codd-real-holders -codd-data-root "$ROOT" -codd-spawn-shell /tmp -codd-shell-argv "/bin/zsh -f"
#   then: quit (⌘Q), `pgrep -lx codd-holder` (still running), relaunch with the same root (reattached),
#   STOP from the row's context menu or `kill -TERM <holderPid>`, and `rm -rf "$ROOT"` once the
#   holders have exited. Add -codd-quit-after 4 -codd-snapshot /path/x.png for unattended runs.
#   Log lines start with REALHOLDERS (spawned / attached / title / cwd / exit / closed / error).

# Terminal spike
cd Spikes && xcodegen generate
xcodebuild -project TermSpike.xcodeproj -scheme TermSpike -configuration Debug -derivedDataPath ../build/spike \
  -skipPackagePluginValidation -skipMacroValidation build     # or: test
# measurements: build -configuration Release, then
../build/spike/Build/Products/Release/TermSpike.app/Contents/MacOS/TermSpike --probe   # ~10 s
../build/spike/Build/Products/Release/TermSpike.app/Contents/MacOS/TermSpike --bench   # ~3 min
../build/spike/Build/Products/Release/TermSpike.app/Contents/MacOS/TermSpike --report  # RESULTS.md from JSON
```

## 7. Known gaps

### Real-holder mode
- **Shells only, no terminal engine:** no ATTACH, OUTPUT, INPUT or RESIZE. Holders run at 120×36 whatever the pane size, the ZSH tab is not wired, and the pane shows a placeholder.
- **Not connected yet:** claude sessions, hooks and cswap. The account store is still the mock.
- **Layout is in memory only:** groups, order, tags, pins and archive are lost on relaunch. Every session lands in 未分類 under a project per cwd.
- **PATH:** the login-shell capture is not used, so PATH falls back to CoddCore's default list. A `zsh -l` session sets its own PATH anyway.
- **Two CODD instances** on the same data root take sessions over from each other. The losing side marks its rows STOPPED and does not retry.
- **`holder.log`** in each session folder is append-only. It is small: it records connections and lifecycle only.
- **Deleting a data root while a holder lingers:** the holder re-creates `root/run/` while it re-binds, until its 10 s linger ends. Seen once during cleanup.

### Holder
- Claude's startup probes go unanswered while no client is attached (critique M1, decision 7).
- The holder never sends PING. EXIT can arrive before the replayed OUTPUT, so a client must not treat EXIT as the end of the stream.
- Background jobs lose their output once the session leader exits (normal terminal behaviour).

### ARCHITECTURE.md is behind the code (the integrator may not edit it)
- **Replay start points:** leaving the alternate screen drops the points recorded on it, `3J` does not count, and the header's `resyncCount` can go down.
- **Flow control:** the threshold is min(4 MiB, ring / 2).
- **Protocol extras:** the additional WELCOME and meta.json fields, the ERROR codes and the capability names.
- **Holder binary location:** it now runs from `Contents/MacOS/codd-holder` inside the app (see decision 15).

### Core
- Other components must use the new pieces: call `relaunchBaseline` on every launch, and pass the latest hook `session_id` as `resumeClaudeSessionId`.
- Not verified: running `codd-hook` by an absolute path that contains spaces, and the login-shell capture with your real rc files.
- Registry, layout-store and atomic-file calls must run off the main thread.

### Shell
- NOTES, STATUS and Settings are placeholders.
- Not working yet: New Claude session, Quick note, pause notifications, Retry and Take over, and the notes, files and ⌘J buttons.
- ⌘P and ⌘. are not global shortcuts. The row hover card is missing.
- RUNNING rows in the panel follow tree order.
- The traffic lights sit at the native position.

### Spike
- **Needs the screen unlocked:** a rerun of every visible-window row and the 注音 key pass.
- **Not measured:** frame times, keystroke-to-glyph latency, session-switch latency with a real engine, and reattaching after a kill mid-stream.

### Smoke tooling
- The smoke script lives in the scratchpad, not the repository.

## 8. Decisions for you

The first three block M1. The rest can be answered as the related work comes up.

1. **Terminal engine.** Rerun `TermSpike --probe` and `--bench` with the screen unlocked and do the manual checks in `Spikes/TermSpike/MANUAL-TEST.md` (注音 checks A8, B9–B11, Ctrl+C during composition) before choosing. Each choice brings follow-up decisions:
   - **Ghostty:** expose replay by forking or patching the libghostty-spm wrapper, or accept the reflection workaround. CODD must also rebuild the surface after a session exits. Choose the cursor-blink default (blinking costs about 225 MiB).
   - **SwiftTerm:** set `CLAUDE_CODE_FORCE_TERMINAL_IMAGES=1` for inline images? Fix Shift+Enter outside the kitty protocol? Parse on a separate thread from the PTY read?
2. **Signing identity.** Everything is ad-hoc signed now; the holder's identifier is pinned to `app.fancycodd.codd-holder`. Needed before M2 so macOS privacy permissions (TCC) are attributed to CODD.
3. **`TERM_PROGRAM`:** unset, `ghostty` or `CODD`. It controls Claude's Cmd+click workaround, notification method and OSC 8 links, independently of the engine.
4. **What the 2.5 MB holder budget measures:** footprint (about 1.6 MB, the reviewers' recommendation) or ps RSS (about 2.45 MB idle, and much more with a full ring because the ring file counts).
5. **Flow-control threshold:** document min(4 MiB, ring / 2), or lower it. At 4 MiB the spike measured 29–34 ms added to Ctrl+C.
6. **Freeze protocol v1:** write the extra WELCOME and meta.json fields, the ERROR codes, the capability names, the replay start-point rules and the EXIT-before-ATTACH ordering into ARCHITECTURE.md.
7. **Startup probes while detached (critique M1):** the holder answers them itself, or the app attaches a hidden surface until the first reply arrives.
8. **The 150 MB/s `cat` budget:** it cannot be reached through a macOS PTY (146–165 MiB/s ceiling, 1 KiB per read). Relax it.
9. **State model:**
   - Sign off the desktop extensions: StopFailure becomes ERROR, PreCompact/PostCompact give COMPACTING, `idle_prompt` keeps ERROR, plus the subagent counter.
   - A manual `/compact` ends in IDLE.
   - When claude has ended but the PTY is still alive, show IDLE (the web rule) or SHELL (SPEC §3 / critic C11)?
10. **Auto-switch:**
